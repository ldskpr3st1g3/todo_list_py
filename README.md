# DailyPlanner

## Название проекта
**DailyPlanner** — веб-приложение для планирования и управления распорядком дня.

## Назначение
Приложение предназначено для帮助用户 (помогает пользователям) эффективно управлять своим временем, структурировать ежедневные задачи, устанавливать приоритеты и отслеживать прогресс выполнения дел для повышения личной продуктивности.

## Целевая аудитория
* Студенты и школьники для планирования учебы, дедлайнов и отдыха.
* Фрилансеры и удаленные сотрудники для разграничения рабочего и личного времени.
* Любые люди, стремящиеся организовать свой день, бороться с прокрастинацией и вести учет своих дел.

## Описание предметной области
Предметная область охватывает процессы **личного тайм-менеджмента и ежедневного планирования**. Она включает в себя управление временными ресурсами пользователя: постановку целей, распределение задач по временным интервалам, группировку дел по сферам жизни (работа, учеба, хобби), установку приоритетов, а также анализ и отслеживание статуса выполнения (запланировано, в процессе, завершено, отложено).

## Основные сущности
1. **Пользователь (User)** — владелец аккаунта, имеющий свои настройки и персональное расписание.
2. **Задача (Task)** — базовая единица планирования. Включает название, описание, время начала, длительность, приоритет и статус выполнения.
3. **Категория (Category)** — метка или тег для группировки задач (например, «Учеба», «Спорт», «Быт»).
4. **Временной блок (TimeBlock)** — конкретный отрезок времени в расписании, к которому привязана одна или несколько задач.

## Основные функции
* **Управление аккаунтом:** регистрация, авторизация, аутентификация и управление профилем.
* **CRUD задач:** создание, просмотр, редактирование и удаление задач и событий.
* **Планирование:** привязка задач к конкретным датам, установка времени начала и окончания.
* **Категоризация и приоритеты:** присвоение задачам категорий и уровней важности.
* **Фильтрация и поиск:** просмотр задач по дате, статусу, категории или ключевым словам.
* **Визуализация:** отображение расписания в виде удобного списка на день или таймлайна.
* **Статистика:** базовый подсчет выполненных задач и анализ продуктивности за период.

## План развития проекта
Проект будет развиваться итеративно, начиная с быстрого прототипа и переходя к высоконагруженной архитектуре:

1. **Этап 1: MVP на Python (Прототипирование)**
   * Проектирование реляционной базы данных (PostgreSQL).
   * Разработка REST API на Python (FastAPI или Django) для быстрого старта.
   * Реализация базовой авторизации (JWT) и CRUD-операций для задач.
   * Создание минимального веб-интерфейса.
2. **Этап 2: Углубление бэкенда и бизнес-логики**
   * Добавление фоновых задач (например, отправка уведомлений о приближающихся дедлайнах) с использованием Celery/Redis.
   * Реализация сложной фильтрации, сортировки и базовой аналитики.
   * Покрытие кода тестами и настройка CI/CD.
3. **Этап 3: Миграция на Rust / C++ (Высокопроизводительный бэкенд)**
   * Переписание наиболее нагруженных микросервисов (например, движка уведомлений или аналитики) на **Rust** (Axum/Actix) или **C++** (Drogon) для повышения производительности и изучения этих языков в реальных бэкенд-задачах.
   * Настройка взаимодействия между Python-оркестратором и Rust/C++ сервисами через gRPC или REST.
   * Оптимизация работы с базой данных и внедрение кэширования на уровне нового бэкенда.
